# 拾光二手交易系统

## 项目简介与运行范围

使用 Python、Tkinter/ttk 和 SQLite 实现的二手交易桌面系统，提供商品发布与审核、搜索、咨询、预约、邮寄与面交、评价和举报处理。

不同账号连接同一个本地数据库，以商品归属和交易关系区分买卖操作。软件不提供跨设备联网服务；支付在线下完成，快递公司和运单号由卖家录入，未接入真实支付、退款或实时物流查询。

## 快速运行

### Windows 可执行程序

解压完整提交包，进入 `code/运行程序/`，双击 `拾光二手交易系统.exe`，无需预先安装 Python。必须保留同目录的 `_internal/` 及其动态库、资源和许可证，不能单独复制 exe。

空库首次启动会显示管理员初始化窗口，填写管理员登录名和密码后进入登录页。普通用户在登录页注册；空库没有预设账号或演示密码。

exe 默认数据库为 `%LOCALAPPDATA%\ShiguangMarket\market.sqlite`。

### 源码运行

需要 Python 3.12 或更新版本，并安装 Tkinter（Windows 官方 Python 安装程序通常自带）。以下命令均在 `code/` 目录执行：

```powershell
python -m pip install .
python run.py
```

源码默认数据库为用户主目录下 `.secondhand-market/market.sqlite`。也可以明确选择另一份数据：

```powershell
python run.py --db .local/market.sqlite
```

这个命令使用 `code/.local/market.sqlite`，与不带参数的源码启动及 exe 默认位置不同。切换账号时应使用同一数据库；更换路径会打开另一份数据。

## 账号与权限

普通用户使用手机号注册、登录，同一个账号可以出售自己的商品并预约他人的商品，不能预约自己的商品。商品编辑、预约处理、消息和交易详情都按实际归属或参与关系检查权限。

管理员使用独立登录名，并在登录界面勾选“管理员登录”。普通注册不能取得管理员权限。首次窗口用于初始化本机管理员；源码还提供交互式命令，密码在提示后输入：

```powershell
python run.py --db .local/market.sqlite --create-admin admin
```

管理员负责商品审核、举报核实、分类与用户状态管理、统计及日志查询。注册手机号、完整地址和交易联系方式不会随公开商品资料返回。

## 主要功能及使用流程

1. **发布与审核。** 在“我的商品”创建草稿，填写商品信息，添加图片并设置邮寄或面交方式。草稿可以分次保存，提交审核时检查必填内容。管理员查看商品及图片，通过后发布，或填写原因驳回。已发布商品的相关编辑需要重新审核，有效预约期间限制修改。
2. **搜索与咨询。** 在“发现商品”组合筛选关键词、分类、价格、状态、成色、地区和交付方式。选中商品后打开详情，可收藏或咨询卖家。地区筛选忽略前后及中间空格，支持城市、区县或组合地区的包含查询，例如“北京”“海淀区”“北京市 海淀区”；百分号和下划线按普通字符匹配。
3. **预约。** 买家在详情发起预约，选择卖家支持的交付方式。商品从“已发布”变成“已预约”，预约记录为“待确认”；卖家同意后商品与预约均进入“待交易”。同一商品只能有一条有效预约，等待卖家处理满24小时会按规则超时取消。
4. **邮寄。** 买家先在个人中心保存收货地址，再预约并选择地址。卖家同意后，交付状态为“待发货”；在订单详情填写快递公司、运单号及发货信息后变为“已发货”。买家收到实物后确认收货，预约变为“已完成”、商品变为“已售出”。发货后不能直接按未发货订单取消。手动录入运单不代表真实物流签收。
5. **面交。** 双方约定地点与时间。卖家同意后交付状态为“面交中”，交接后由卖家发起完成确认，进入“待面交确认”，再由买家确认结束。私密交接资料按当前交易参与关系开放。
6. **评价与举报。** 完成交易后可提交真实交易评价。商品详情及相关交易记录提供举报入口，可查看自己的举报和结果通知。管理员核实并记录理由；在途订单与商品公开销售分别处理。异常方案的接收方可以接受或拒绝，方案提出方可以撤回自己的方案后重新提议；异常发起人可撤回未结异常。拒绝或撤回方案仍保留协商，撤回异常也不会自动完成交易或释放在途商品。处理记录在订单详情中保留。

“商品状态”表示能否发布或出售，“预约状态”表示购买意向是否生效或结束，“交付状态”表示发货、交接及收货进度，三者分别保存并同步检查。

## 源码结构与实现位置

```text
code/
├── run.py                    源码启动入口
├── src/marketplace/
│   ├── __main__.py            参数、默认数据路径与首次设置
│   ├── app.py                 Market 服务组合
│   ├── auth.py / accounts.py  身份验证、资料与后台账号管理
│   ├── products.py / media.py 商品状态、审核与图片处理
│   ├── bookings.py            预约、版本和重复请求处理
│   ├── delivery.py            邮寄、面交和履约协商
│   ├── addresses.py / places.py 地址簿及面交地点
│   ├── queries.py             商品查询、订单资料及统计
│   ├── messaging.py / social.py 咨询通知、收藏和关注
│   ├── reports.py / reviews.py 举报与评价
│   ├── db.py / migration4.py / migration5.py 数据库事务和迁移
│   ├── ui.py / ui_features.py / ui_delivery.py 页面与操作入口
│   ├── ui_widgets.py / ui_extras.py / ui_setup.py 通用弹窗、图片及初始化
│   └── ui_theme.py            全部窗口共用的字体和控件字号
├── tools/                    风格检查、统计、构建和提交包脚本
└── 运行程序/                 Windows exe 及完整运行依赖
```

`base.py` 提供服务共用的权限与记录操作，`domain.py` 集中业务状态、输入校验及时间处理。界面调用服务，服务校验并通过 `Store` 访问数据库；业务规则不依赖某一个按钮入口。

## 数据保存与构建

账号、商品图片、地址、预约、消息及操作记录存入所选 SQLite 数据库。关闭程序后备份数据库；同时保留自动生成的迁移备份。图片内容保存在数据库中，移动原始上传文件不会影响已保存图片。更新软件时保留原用户数据目录，不覆盖正在使用的数据库。运行日志与数据库同名，扩展名为 `.log`。

源码构建 wheel 和源码分发包：

```powershell
python -m pip install -r requirements-dev.txt
python tools/tasks.py lint
python tools/tasks.py count
python tools/tasks.py build
```

构建结果位于 `.local/dist/`，检查输出位于 `.local/checks/`。这些命令不依赖测试目录或测试专用依赖。

在 Windows x64 上重新生成独立 exe：

```powershell
python -m pip install -r requirements-exe.txt
python tools/build_windows.py
```

结果位于 `.local/windows/拾光二手交易系统/`。wheel 是供 Python 安装的包；PyInstaller 生成的是包含 Python 运行时的目录，两者用途不同。分发 exe 时复制整个运行目录，勿删第三方依赖及许可证。
