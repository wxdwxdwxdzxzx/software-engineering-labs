# AI 辅助设计与审查记录

工具：本次 Codex 会话。模型精确标识未由当前可核验的工具界面提供，报告不虚构具体型号。设计依据：实验二手册与本仓库 `lab1-final` 的 `requirements.md`、`chat.txt`、`report.pdf`。本文件记录本次 AI 辅助产物及实际核对，不冒充学生本人手工作图或亲身体验。

## AI-01 架构和 UML 初稿

- 使用场景：按用户任务生成类图、组件图、状态图、时序图的 PlantUML 源文件。
- 输入：实验二要求、实验一全部已确认需求；强调权限、审核、预约状态同步、并发、超时、举报、日志和统计，待确认规则不可擅定。
- 生成结果：`UML/*.puml` 四份，初稿提交 `78fb2c2`。
- 优点：迅速把需求分配到实体、模块、状态和交互视角，便于发现遗漏。
- 问题与审查：实际运行 PlantUML 后，类图中文类名别名写法报语法错误；组件图连接过多导致线条和标签交叉。状态图横向布局过宽。
- 修改优化：将类名写成带引号的显示名，重组组件与数据访问层、删去拥挤的连线标签；状态图改为纵向布局。再次执行 `-checkonly` 和 PNG 导出，检查四图。图中的数据库字段属于设计草案。

## AI-02 UI 初稿与权限审查

- 使用场景：为账号、商品查询、发布、预约、举报、管理员审核与统计设计可编辑界面。
- 输入：REQ-001～REQ-036 中的权限、正常/异常结果；要求展示空状态、旧页面、重复预约、违规处理等边界。
- 生成结果：Python 生成 11 张可编辑 SVG 初稿，提交 `c7bd8ce`。
- 优点：统一导航、颜色、字号和交互布局，能快速覆盖多个角色。
- 问题与审查：初稿把买家和卖家放在同一“我的预约”界面，并给买家展示了卖家专属的“确认交易完成”操作；普通用户导航也露出了管理后台入口。
- 修改优化：导航按角色显示；预约界面拆分为买家和卖家两张。复核卖家同意/拒绝、买家取消、双方取消、卖家确认的操作权限。在线 Figma/Pixso 未能通过当前浏览器自动化可靠操作；SVG 由脚本生成，实际安装的 Inkscape 1.4.4 负责读取并导出 PNG，保留可编辑 SVG 设计源文件；不冒充 Figma/Pixso 成果。

## AI-03 报告草稿与对照审查

- 使用场景：整理模块划分、数据存储、四类图说明、UI 说明、追踪矩阵和版本信息。
- 输入：本仓库真实生成的 UML、UI、需求追踪矩阵及实际 Git 提交；报告要如实说明 AI 的作用与局限。
- 生成结果：`实验报告.pdf` 与可重建脚本 `设计源文件/build_report.py`。
- 优点：可把四种 UML、十二张 UI 和逐条追踪关系整理到统一的报告结构中，减少重复排版。
- 局限：自动排版可能出现分页空白、图中文字过小或版本信息不准确，文字流畅也不能代替与源文件的核对。
- 审查与优化：逐页渲染 PDF，检查图像清晰、标题、分页和所列文件；用程序检查 38 条需求的映射、四对 PNG/PUML、全部 UI PNG、ZIP 结构及 Git 工作区。具体核验结果以脚本输出和最终文件为准。

## 给本人核对的反思草稿

AI 能把访谈需求迅速转成多个相互参照的图，但图的存在不等于设计正确。此次类图曾出现实际语法错误，组件图布局拥挤，UI 初稿还把卖家按钮显示给买家。只有将每条需求与图和界面逐项对照、实际渲染并检查角色及状态，才能发现这些问题。“AI 生成—自动规则检查—人工确认”适合作为工作流；人主要负责检查校对是否可行，取决于需求是否明确、检查是否覆盖关键冲突，以及最终是否有人对业务决策负责。上述反思是供王旭东本人审阅修改的草稿，不声称是其已完成的个人体验记录。
