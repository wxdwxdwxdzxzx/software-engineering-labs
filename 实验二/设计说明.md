# 二手交易系统设计说明

## 依据与边界

以本仓库 `lab1-final` 中的 `requirements.md` 为基线。买家和卖家共用普通用户账号，管理员使用独立账号。系统负责商品信息展示、预约意向、审核、举报、日志和统计，线下交易完成后由卖家确认；不设计真实支付或物流接口。

## 模块及接口

1. 认证与权限：手机号注册登录、唯一性校验、管理员后台鉴权；所有写操作在服务端复核角色和商品归属。
2. 商品与审核：草稿、待审核、驳回、已发布、下架、售出及违规处理；改价或描述触发重新审核。
3. 预约与交易：创建有效预约、卖家同意/拒绝、买家等待期取消、双方待交易期取消、卖家确认完成；协调商品与预约状态。
4. 举报与站内通知：举报原因、管理员核实、违规下架及结果通知；通知渠道为乙方设计范围限定。
5. 查询与统计：买家组合搜索、卖家自有商品状态筛选、管理员每日新上架和分类在售统计。
6. 操作日志：商品状态变化、预约变化、审核及举报处理；系统自动超时记为 SYSTEM。
7. 超时任务：只处理仍处于待确认且满24小时的预约；重复运行不得再次改写终结记录。

## 数据存储草案

关系型表：`users(id, phone UNIQUE, username UNIQUE, password_digest, contact)`、`admins(id, login_name UNIQUE, password_digest)`、`products(id, seller_id FK, title, description, category, price, status, version, created_at)`、`reservations(id, product_id FK, buyer_id FK, status, created_at, handled_at)`、`reports(id, product_id FK, reporter_id FK, reason, result)`、`notices(id, recipient_id FK, content, created_at)`、`audit_logs(id, actor, time, type, target_id, before_state, after_state)`。字段是设计草案，不宣称甲方逐字段确认；实施时再定详细类型和索引。

预约创建、同意、拒绝、取消、完成、超时与违规下架均需在一次业务事务内处理关联状态和日志。对同一商品建立“最多一条有效预约”的数据库约束或等效原子校验，重复点击先辨认本人现有有效预约；旧页面提交时以服务端当前状态为准。联系方式由当前预约状态和参与者身份决定显示权限，不以页面曾经显示为准。

## UML 选择

类图呈现持久实体、关联与唯一性；组件图呈现功能模块及交互；状态图呈现商品生命周期与禁止转换；时序图呈现并发预约、重复点击和旧页面校验。四图覆盖结构、行为和交互三类，其中类图为必画图。

## UI 制作

在线 Figma/Pixso 未能通过当前浏览器自动化可靠操作，因此改用实际安装的 Inkscape 1.4.4 制作可编辑 SVG 并导出 PNG。SVG 初版由本次 Codex 会话生成，随后按需求检查权限和异常场景并修正（如将买家与卖家预约处理分为两个界面）。PNG 由 Inkscape 命令行从 SVG 导出；不是 Figma/Pixso 成果，也不是软件运行截图。界面中的数字、商品和日志仅为说明用样例数据。
